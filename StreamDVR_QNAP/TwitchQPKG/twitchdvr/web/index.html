Ustawienia

🔒 Ustawienia zablokowane

Panel nagrywania działa normalnie. Aby edytować tokeny Twitch/Kick i ustawienia, podaj hasło administratora.

Hasło panelu

Hasło nie jest nigdzie przechowywane, a klucz (wyprowadzany z hasła) istnieje tylko w pamięci i nigdy nie jest zapisywany ani wyświetlany w panelu — opis AES-256-GCM/PBKDF2 to tylko nazwa mechanizmu. Po ustawieniu hasła tokeny Twitch/Kick trafiają zaszyfrowane (AES-256-GCM, klucz PBKDF2) w pliku settings.enc zamiast do otwartego config.json. Po restarcie QNAP ustawienia wracają do stanu zablokowanego — bez hasła nikt nie odczyta tokenu ani zmieni ustawień. Nagrywanie i kanały działają dalej bez hasła.

Logowanie Twitch

● Zalogowano jako
twitch.tv → F12 (DevTools) → Application → Cookies → twitch.tv → skopiuj wartość auth-token. Przycisk 👁 pokazuje wklejony token, żeby można było sprawdzić, czy jest kompletny.

Logowanie Kick

● Zalogowano jako
Zaloguj się na kick.com w oknie, które otworzy przycisk Otwórz kick.com (przeglądarka nie może automatycznie odczytać ciasteczek kick.com — stąd ręczne kopiowanie). Potem: F12 (DevTools) → Network → kliknij dowolny request do kick.com → Request Headers → kliknij prawym na cookie: → Copy value → wklej tutaj CAŁĄ linię (np. session_token=...; kick_session_id=...; kick_session=...; __session=...). Każda para nazwa=wartość musi zostać. Logowanie jest opcjonalne — nagrywanie działa też bez niego, a usługa sama wyśle ciasteczka w zapytaniach do kick.com.
